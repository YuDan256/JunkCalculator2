# 构造与析构的语义

本文记录 JC2 中 `init` / `finalize` / 字段初始化器（内部名 `<fieldinit>`）的行为契约。
结论均由探针实测（`test/tests/features/test_lifecycle.jc2` 固化），不是读码推断。

## 存储模型

三者都不是普通属性，而是类上的专用槽位（`ObjClass::initFn` / `finalizeFn` / `fieldInitFn`）：

- 不占用 `properties` / `members` 的键位，因此不会被继承平铺、反射列出或动态索引访问；
- 查找沿 `parent` 链取第一个非空的槽位（字段初始化器例外，见下）；
- 序列化随 CLASS 记录单独写出（工作区格式 VERSION 10）。

## 构造

实例化顺序固定为：

1. 分配实例并写入目标寄存器（先成为 GC 可见对象）；
2. 按类模板快照公开属性与私有属性；
3. 执行字段初始化器：沿 `parent` 链**派生优先**，每级先跑该级 traits（声明顺序），再跑该级自身的字段初始化器；
4. 调用 `init`（沿链取第一个定义者）。

由此得到的契约：

| 情形 | 行为 |
|---|---|
| 子类没有 `init` | 使用继承来的（父类的）`init` |
| 字段默认值 | 在 `init` 执行前已就绪 |
| `super.init()` | 在书写位置执行，可见"父类构造夹在中间"的效果 |
| `super.init()` 多次 / 在循环里 | 编译期报错 |
| 父类没有 `init` 却调用 `super.init()` | 运行期报 `Parent class has no method '<init>'.` |
| 有字段默认值但没有用户 `init` | 自动合成一个空的 `<init>`，使子类的 `super.init()` 仍可解析 |
| trait 提供 `init` | 作为默认构造器：消费者类自己没有 `init` 时使用它 |

## 析构

| 情形 | 行为 |
|---|---|
| 父子都定义 `finalize` | 只执行**最派生**的那一个 |
| 子类没有 `finalize` | 继承父类的 |
| 需要两级都执行 | 在子类 `finalize` 里显式调用 `super.finalize()`（每次 `finalize` 最多一次，不能在循环里） |
| 每个对象 | 至多执行一次；触发时机不可预测（GC 时，或正常退出时的那一轮 GC） |
| `finalize` 内抛异常 | 被静默忽略并打印到 stderr，不中断 GC |

## trait 与字段初始化器

trait 的字段初始化器**按声明它的类执行，且只执行一次**：构造时遍历各级 traits 各跑一份，
不平铺进宿主。`init` 与 `finalize` 则作为默认实现传给宿主（宿主自己定义了就不覆盖）。

## 修饰符与可见性

- `local` / `const` 等修饰符对生命周期钩子没有意义，写了也照常执行（不会变成私有属性而失效）；
- 生命周期钩子不出现在 `getFields` / `hasField` 中，也不能通过动态索引访问。

## 子类与祖先的私有属性

子类方法**不能**引用祖先声明的私有属性：编译期在子类里找不到该声明，会按公开属性访问处理，
运行期得到"属性不存在"的错误。这是设计使然，不是缺陷。
