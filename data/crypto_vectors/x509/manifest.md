### Notes on the table

- `neg_tampered_sig.der` is a byte-for-byte copy of `leaf_rsa.der` with **one** byte changed: the last byte of the file (`0xAB` -> `0x54`, offset 913). That byte is inside the `signatureValue` BIT STRING, which is the final element of a `Certificate`, so the DER framing stays valid and the structure still parses.
- `neg_truncated.der` is `leaf_rsa.der` with the last 50 bytes removed. `neg_garbage.der` is 64 fixed bytes: `DE AD BE EF` repeated 16 times.
- `neg_ca_false.der` carries `basicConstraints=critical, CA:FALSE` and a `keyUsage` without `keyCertSign`, yet it signs `leaf_under_cafalse.der`.
- `neg_pathlen_root.der` carries `basicConstraints=critical, CA:TRUE, pathlen:0` yet has a subordinate CA (`neg_pathlen_inter.der`).
- `neg_self_signed.der` is a self-signed end-entity certificate (`CA:FALSE`) — a private/self-signed server certificate that is simply not in the trust store. OpenSSL reports error 18 `self-signed certificate`.
- For `neg_tampered_sig.der`, `neg_truncated.der` and `neg_garbage.der` the subject/issuer/SAN/date columns are read back from the DER file itself; `n/a` means OpenSSL could not parse it (which is the expected outcome for the latter two).

## Reproducibility notes

- Re-running `generate.ps1` reuses `keys/*.pem` and rewrites every DER file plus this manifest, so the manifest can never disagree with the files on disk.
- Serial numbers are deterministic: each CA section starts from a fixed seed in `work/ca/<ca>/serial` and `openssl ca` increments it per issuance. (`rand_serial` must **not** appear in the config: OpenSSL 3.2.1 then ignores the serial file and emits 20 random bytes.)
- `work/` is scratch space: `work/pem/` holds the PEM copies used by the verification commands (and by `generate.ps1 -Check`), the CA databases under `work/ca/` are deleted once generation succeeds. The only private keys that persist are the ones in `keys/`.
- RSA-2048 signature values are always 256 bytes, so RSA certificate sizes are perfectly stable. ECDSA signatures use a randomised nonce, so re-running with `-ForceKeys` can shift an EC certificate by 1–2 bytes; use `generate.ps1 -Check` to confirm this manifest still matches the files on disk.
