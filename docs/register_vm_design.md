# JC2 寄存器虚拟机重构架构设计

本文档记录了将 JC2 引擎从基于栈的虚拟机（Stack-based VM）重构为基于寄存器的虚拟机（Register-based VM）的核心架构设计与演进路线。

## 1. 指令集架构 (ISA) 设计
采用经典的 **32-bit 定长指令集**，以最大化虚拟机的解码（Decode）和分发（Dispatch）效率。指令分为三种基础格式：

*   **格式 A (iABC)**: `[OpCode: 8位] [A: 8位] [B: 8位] [C: 8位]`
    *   用于算术运算、逻辑运算等。例如 `ADD A B C` (`Reg[A] = Reg[B] + Reg[C]`)。
    *   **常量复用 (The "K" Bit)**：B 和 C 的最高位（第 8 位）若为 `1`，则表示该操作数是常量池索引（0~127），否则为寄存器索引（0~127）。
    *   **超量常量回退 (Constant Fallback)**：如果常量池索引 >= 128，无法直接塞入 7 位空间。编译器会先发射一条 `LOADK` 指令（格式 B），将该常量加载到保留的暂存器（如 R125）中，随后在主指令中将其作为普通寄存器操作数使用。
*   **格式 B (iABx)**: `[OpCode: 8位] [A: 8位] [Bx: 16位无符号]`
    *   用于加载大常量、全局变量访问、闭包创建等。
*   **格式 C (iAsBx)**: `[OpCode: 8位] [A: 8位] [sBx: 16位有符号]`
    *   用于条件跳转、循环等控制流。

## 2. 寄存器分配与溢出机制 (Register Spilling)
物理指令限制了最多寻址 256 个寄存器。为了支持无限数量的局部变量和复杂的嵌套表达式，采用**寄存器溢出（Spilling）**策略，而非指令前缀扩展。

*   **统一内存模型**：复用现有的 `Value stack[]`。`stackBase` 到 `stackBase + 255` 作为**物理寄存器区**，`stackBase + 256` 之后作为**溢出槽区 (Spill Slots)**。
*   **虚拟寄存器**：编译器前端分配无限的虚拟寄存器，由寄存器分配器映射到 0~255 的物理寄存器。
*   **驱逐与恢复**：当物理寄存器耗尽时，分配器挑选牺牲者，发射 `STORE_EXT A, Bx` 将其存入溢出槽；需要时发射 `LOAD_EXT A, Bx` 恢复。
*   **暂存器保留**：硬性保留 3 个物理寄存器（如 R253, R254, R255）作为暂存器，确保在所有操作数均被溢出的极端情况下，依然有物理寄存器可用于执行基础运算指令。

## 3. 函数调用约定 (Calling Convention)
采用**零拷贝传参**的连续寄存器调用约定。

*   **常规调用**：参数存放在连续的物理寄存器中。执行 `CALL` 时，新帧的 `stackBase` 直接指向第一个参数所在的物理寄存器。
*   **极端调用 (CALL_EXT)**：当参数数量过多，无法放入物理寄存器时，编译器将参数连续分配在**溢出槽**中，并使用 `CALL_EXT` 指令。VM 执行时，将新帧的 `stackBase` 指向溢出槽的起始位置，对新函数而言，这些溢出槽天然成为了它的 `R(0)`、`R(1)`，完美实现跨越物理限制的零拷贝。

## 4. 编译器中端与 IR 设计 (Middle-end & IR)
为了支持高级的寄存器分配和优化，编译器从“单遍（Single-pass）”升级为包含中端和中间表示（IR）的架构。

*   **静态单赋值 (SSA)**：所有变量每次赋值都会产生新的版本（如 `a_1`, `a_2`），生命周期极其清晰。
*   **节点海 (Sea of Nodes)**：采用类似 V8 TurboFan 的图状 IR 结构，放弃传统的线性基本块（Basic Blocks）和三地址码（TAC）。数据依赖和控制依赖均表示为图中的边，极大提升了常量折叠、死代码消除等优化的潜力。
*   **Phi (Φ) 节点去结构化**：在控制流汇合点使用 Phi 节点解决变量状态不一致问题。在最终生成字节码阶段，Phi 节点会被“去结构化”，自动在各个前驱分支的末尾插入 `MOVE` 或 `LOAD_EXT` 指令，确保运行时物理寄存器状态的绝对正确，VM 层面无需感知 Phi 的存在。
