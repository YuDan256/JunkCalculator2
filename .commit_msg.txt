feat(lsp): offline symbol collector + sidecar json import resolution

【动机】
LSP 解析 import 时通过 LoadLibrary + 跑 jc2_extension_init 收集符号，会触发 dll 的 DllMain/静态初始化副作用。改为「构建时离线收集符号 → sidecar json → 运行时读 json」，LSP 完全不碰 dll 二进制。同时把 documentation.json 从 exe 剥离到 bin/data/（数据外部化）。

【原理】
1. 新增符号收集器（src/lib/collect_api + collect_main）：构建时直接编译 dll 模块的 jc2_init 源码，用「只收集」的 host API（register_function/make_class/bind_method/help 真实收集，其余 80+ 函数是安全桩）跑它，收集精确 arity/paramNames/help 到 lib/xxx.json。
2. CMake 为每个内置 dll 模块编译收集器并在 POST_BUILD 生成 sidecar，与 xxx.dll 成对放 lib/。第三方 dll 作者用同一工具生成 sidecar 随 dll 分发，机制一致。
3. NameResolver::handleImport 改为读 lib/xxx.json（sidecar），不 LoadLibrary；无 sidecar 时宽容降级（符号未知、不报未定义）。
4. documentation.json 外部化：HelpRouter 读 bin/data/documentation.json，删除 GeneratedHelpText.h 编译期嵌入。
