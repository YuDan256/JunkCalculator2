## 1. 问题：合成时的分支穿越

`cas.integ` 曾返回**符号相反**的原函数（已由 `aebe284` 的两道防线消除"给错答案"，
但根因未除）。链条如下（全部实测，`p = sym("p")`）：

```
cas.integ(p^2/sqrt(1-p^2), p)
  → Radical Substitution，u = sqrt(1-p^2)
  → 内层被积函数 -i*sqrt(p^2-1)，命中表项（表项本身正确）
  → 回代：纯语法 subs(u -> sqrt(1-p^2))
       sqrt(u^2-1) 里的 u^2-1 化简成 -p^2，再经 trySquareRoot
       拆成 sqrt(-1)*sqrt(p^2) → i*p
  → log 项因此落到另一支，整个结果取反
```

**关键观察：各部件在各自的分支上都正确。** 内层表项经 `cas.verifyInteg` 在复数测试点上
通过；`sqrt(-p^2) = i*p` 对 `p > 0` 也是主分支的正确取值。错的是**合成**：正变换与回代
各自选了使局部成立的分支，合成后整体跨了分支，于是合成结果不等于值的合成。

因此靠"修某一条规则"治不了；要让重写规则**携带并检查前提条件**。

**当前的两道临时防线**（`aebe284`）只能**拒绝**，不能**给对**：
1. 策略循环自检 → 跳过可疑候选，让后续策略接手（救回 3/4）
2. `cas.integ` 出口自检 → 仍不可信则抛 `CalculusError`（第 4 例）

对 35 个积分的扫描：临时防线前「31 正确 / 4 错答案」，之后「34 正确 / 1 拒绝 / 0 错答案」。

## 2. 被否掉的 S1（记录理由，勿再提）

**S1：自检失败时先试"反号候选"再拒绝。**

- 依据：实测本类缺陷 **4/4 都是整体符号取反**；并且实验证实
  `p^2*sqrt(1-p^2)` 那例的反号候选数值上正是正确原函数
  （`F'(0.5) = +0.216506`，原候选为 `-0.216506`）。
- 代价极小，且仍不会给错答案。
- **被否理由（作者 2026-09-22 决定跳过）**：它是**启发式**，只覆盖"整体 ±1"型的分支错误。
  分支错误未必表现为整体取反（例如和式里只有一项翻号），那时反号也过不了自检、仍会拒绝。
  既然要做就做真正的分支感知，不要先塞一个只对观察到的几例有效的补丁。

## 3. 核心约束：假设不能挂在节点上

| 事实 | 位置 |
|---|---|
| `SymVar` 只有一个 `std::string name`，没有任何前提/假设字段 | `Symbolic.h:361` |
| 节点在全局 intern 池里按 `hashValue + equals` 去重，同名变量全局**只有一个节点** | `Symbolic.cpp:212`（`SymPool::intern`）、`Symbolic.cpp:237`（`SymExpr::intern`） |
| `SymNum` 的 `hashValue` 由数值哈希决定，节点身份按表示严格区分 | `Symbolic.cpp:773` |

**推论**：若把假设挂在 `SymVar` 节点上，`assume(p>0)` 之后所有 `p` 都变成带假设的节点，
与池中已有的 `p` 不再是同一个 —— 要么让池按假设区分（intern 语义整体改变，
`equals`/`hashValue` 全线受影响），要么干脆不 intern 变量（`SymExpr::operator==`
的指针快路径失效，性能与去重都退化）。

⇒ **假设必须放在独立的"假设环境"里，按变量名查，随调用链传递**，节点模型不动。

### 4.1 D4 定稿：`cas.assume(p, "positive")`

```jc2
cas.assume(p, "positive")     // 设置：p 是符号，第二个参数是标签
cas.assumptions()             // 查询 -> Dict{"p": "positive"}（与 regex.getcontext() 同风格）
cas.clearAssumptions()        // 清空
```

**作用域：全局**，与现有 `SymConfig`（`debugIntegration` / `maxDepth` 等）一致，
不做传参穿透；但**必须提供清空入口**，否则陈旧假设会污染后续计算。

#### 为什么不是 `cas.assume(p > 0)`

**JC2 现在没有符号关系对象**，这个字面写法根本收不到参数 —— 实测：

```jc2
p = sym('p')
p > 0        →   TypeError: Expected a real number.
```

原因是 `SymType` 里没有关系类型（`Symbolic.h:51`）：

```cpp
enum class SymType { NUM, VAR, ADD, MUL, POW, FUNC, CONST };   // 无 REL/比较类型
```

比较运算符是**立即求值**的，`p > 0` 在 `assume` 被调用之前就抛错了。
要写出 `p > 0` 的字面形式，必须先新增符号关系节点（`SymType::REL`），
那要动枚举、打印、`equals`、哈希与全部 switch 分支，并且会碰 §3 的 intern 约束。
标签制 `(符号, 标签)` 零解析、与 D2 对齐，故取之。

**被否的字形（勿再提）**

| 字形 | 否掉的理由 |
|---|---|
| `cas.assume(p > 0)` | 需要先新增关系节点，见上；现状下连参数都传不进去 |
| `cas.assume("p > 0")` | 要写关系字符串解析器；`>=`、负系数、多变量等边界全要自己定，错误信息也差 |
| `cas.assumePositive(p)` 专用函数族 | 函数数随标签数增长（D2b 加区间后更糟） |
| `syntax` 宏造 `assume p > 0` | 最贴合书写，但要在词法层做 DSL，与本方案的假设环境是两件事，另议 |

## 6. 传播机制

假设环境要穿过这些路径，否则等于没做：

| 路径 | 要求 |
|---|---|
| `subs(expr, var, val)` | 代入后**丢弃**被代变量上的假设；对代入值能推出的新前提并入环境 |
| `simplify` / `simplifyCore` | 只读环境，不修改；重写规则查环境决定是否触发 |
| `integrate` | 进入换元时把换元关系（如 `u = sqrt(1-p^2)` ⇒ `u ≥ 0`）**压入**环境（RAII 守卫，退出即还原）；回代时据此选分支，而非让 `trySquareRoot` 猜 |
| `diff` | 只读，无需修改 |
| `solve` / 其它推导入口 | 只读，无需修改 |

环境是 `thread_local` 全局，所以"传递"不靠参数；需要作用域化的只有
**换元边界**（push / restore），其余路径自然继承当前环境。

**对本案的最小充分条件**：只要回代时环境里有 `u ≥ 0`（换元定义域）与"`u^2 - 1` 的符号未知"，
`trySquareRoot` 就不会把 `sqrt(u^2-1)` 化成 `i*p`，穿越即不发生。

## 9. 风险与代价（诚实评估）

- **比最初估计便宜**：假设环境做成 `thread_local` 全局（与 `g_symPool` 同惯例，
  `Symbolic.cpp:230`），重写规则直接查它，**不需要给 `simplify` / `subs` /
  `integrate` / `diff` 加参数、不改任何签名**。"传播"退化为在换元边界
  push / restore 一组事实（RAII 守卫）。代价集中在：新增环境与三个 API、
  给 `trySquareRoot` 两条规则加守卫、在换元策略里 push 事实。
- **语料预期变化**：D3(a) 若是**全局**保守，部分现在化简的结果会退化成未化简形式。
  这是"宁少化简、不错化简"的取舍。**条数必须先实测**（§7），
  若过多则把保守范围收窄到换元回代这类跨界点。
- **API 是新增概念**：CAS 现在没有任何"假设/条件"概念，用户侧要新增语法或函数。
- **节点 intern 不能动**：动了会牵连 `equals` / `hashValue` / 指针快路径，风险远大于收益。
- **不能承诺"完全消除分支问题"**：本方案消除的是**已知重写规则**的分支穿越；
  `√`/`log` 的多值性在数学上无法通过保守重写完全消除，只能保证"不让重写偷偷改变分支"。

## 12. P1 落地记录（`94d091f`）

### 交付

| 项 | 内容 |
|---|---|
| 假设环境 | 独立 `thread_local`，按变量名查；词汇表 positive / negative / real / nonzero |
| 判据 | `isProvablyNonNegative(expr)`：正数、positive 变量、偶次幂、非负因子之积、非负项之和、`exp(...)` 可证；**未知即 false** |
| 守卫 | `operator^` 的**幂的幂法则**与**乘积分配律**两条（这才是真凶，不在 `trySquareRoot`）；另给 `trySquareRoot` 的两条同族规则加同样守卫 |
| API | `cas.assume(p, "positive")` / `cas.assumptions()` → Dict / `cas.clearAssumptions()` |
| 测试 | `tests/features/test_cas_assume.jc2`；三套 47/47、47/47、18/18 |

### 实测结果

- **语料 3 行变化**，全部是把错的改成不化简：
  `#64 sqrt(x^2) → sqrt(x^2)`（原 `x`）、`#65 sqrt(x^2*y^2) → sqrt(x^2)*sqrt(y^2)`
  （原 `x*y`）、`#67 (x^2)^(1/2) → sqrt(x^2)`（原 `x`）
- **集成路径行为未变**：35 例扫描 34 正确 / 0 错答案 / 1 拒绝，耗时 1.6s —— 与 `aebe284` 一致

### ★ 关键发现：变量级标签不足以支撑换元管线

计划里的"change 3：换元边界 push `u >= 0`"**未实施**，而且实测证明它**不够**：

全局启用守卫后，换元管线里的表达式**爆炸**：
`1/(p^2*sqrt(1-p^2))` 从 `0.05s` 变成**挂死**（30 分钟级）。轨迹显示
`sqrt(p^2)` / `sqrt(sin(p)^2)` / `sqrt(cos(p)^2)` 不再坍缩，替换表达式逐层膨胀，
策略搜索组合爆炸。

原因：**换元策略依赖的正是这些重写**。例如 `√(1-p²)` 用 `p = sinθ` 换元后，
`√(1-p²) = √(cos²θ)`，在 `θ ∈ [-π/2, π/2]`（该策略选定的主分支）上**就是** `cosθ`
—— 拦掉它反而错了。要既正确又不爆，需要的是**表达式级**分支事实（"`cosθ >= 0`"），
而本期词汇表只有**变量级标签**。

故本期以 `branchGuardsActive()` / `ScopedIntegrationScope` 在**推导期间挂起守卫**，
推导过程沿用既有快速路径，由 `aebe284` 的原函数自检兜底。

**⇒ 对 P2 的影响（前置项变更）**：P2（"让回代选分支"）的第一步不再是"push `u >= 0`"，
而是**把事实模型从变量级标签扩到表达式级事实**（一组"已知非负的表达式"，按结构等价查，
带作用域 push/restore）。这是 P2 的必要前置，应写进 P2 的范围。

### 与计划的其它偏差

计划写"分两次提交"（基础设施 / 守卫），实际**合并为一次**：`cas.assume` 的唯一可观察
效果就是经由守卫，拆开后第一个提交无法自洽（测试文件也得人为再拆）。

| 表达式级事实 | `ScopedNonNegativeExpr`：作用域内"已知非负表达式"栈，按结构等价查（指针身份优先，其次节点 `equals`，不做代数回退） |
| 判据接入 | `isProvablyNonNegative` 先查该栈；另补 `cosh` 为无条件可证非负（实参数下 `cosh >= 1`） |
| 策略接线 | ① 三角换元 `A_neg && C_pos` 分支：取 `p = sin t`、`t ∈ [-π/2, π/2]`，声明 `cos(_t) >= 0` 与 `cos(var) >= 0`（子式在 `_t` 下算完又被改名回 `var`，两种形式都要）；② 根式换元：`u = base^(1/n)` 主分支 ⇒ `n` 偶数时 `u >= 0` |

### ★ P2 实测：事实「必要但不充分」

把守卫改成全程生效（临时实验，随后回退）后的对照：

| 配置 | 结果 | 耗时 |
|---|---|---|
| 挂起守卫（P1 现状） | 34 正确 / 0 错答案 / **1 拒绝** | **1.8s** |
| 全程生效 + 表达式级事实 | 33 正确 / 0 错答案 / **2 拒绝** | 46.5s |
| 全程生效、无事实（P1 早期） | —— | **挂死**（30 分钟级） |

- **方向正确**：加入事实后不再挂死（30 分钟级 → 46.5s），证明表达式级事实确实解开了
  大部分换元管线的堵塞。
- **但仍不达标**：2 例原本正确的积分变成拒绝（`p^2/sqrt(p^2-1)`、`1/sqrt(p*(1-p))`），
  且仍慢 30 倍。说明**事实集不全** —— 换元管线还需要别的分支结论。

故 `84705d9` 保留挂起，接线处于**休眠**状态（挂起期间不参与判定），不改变任何现有行为。
**取消挂起的条件**：把事实集补全到"全程生效也不掉正确率、耗时回到秒级"。

### 下一步（P2 续）的具体做法

每次缺什么事实，用 `debugIntegration` 轨迹定位被拦掉的重写，判断它是否**在该换元选定的
分支上成立**；成立就补事实（或像 `hyperbolicSimp` 那样直接为该分支写 `applyRule`），
不成立就不能放行、要改管线。逐步逼近，每步都以「35 例扫描不掉正确率 + 耗时可比」为准。

**备选更干净的路线**：三角换元的双曲分支 (`A_pos`) 本就直接用 `applyRule` 消根式
（`hyperbolicSimp`，见 `Integration.cpp:2496` 一带），圆分支 (`A_neg && C_pos`) 却没有
对应物 —— 补一套圆分支的 `applyRule`（`√(1-sin²t) → cos t` 等，符号由所选区间定）
可能比"补事实 + 全局守卫"更贴合既有代码结构。

## 14. P2 续（`5736e68`）：正确性追平，但代价 100 倍 —— 裁决「暂不取消挂起」

两条路线（① 补事实、② 补圆分支 `applyRule`）**一起做了**：

| 补的东西 | 依据 |
|---|---|
| `sinh t >= 0` 事实 | 三角换元 `A_pos && C_neg` 取 `p = cosh t`、`t >= 0`（`t_back = acosh`）。轨迹定位：`p^2/sqrt(p^2-1)` 曾因缺它而产出错答案 |
| `circularSimp`（圆分支 `applyRule` 集） | 对齐双曲分支的 `hyperbolicSimp`。**只放行 cos 侧**：本换元取 `t ∈ [-π/2, π/2]` ⇒ `cos t >= 0`，故 `√(cos²t) = cos t`、`√(1-sin²t) = cos t` 成立；而 `√(1-cos²t) = \|sin t\| ≠ sin t`（该区间 sin 符号不定），**不放行**。另含与分支无关的平方恒等式 |

### 实测对照（本节结论的依据）

| 配置 | 正确性 | 耗时 |
|---|---|---|
| 挂起守卫（P1 现状） | 34 正确 / 0 错答案 / 1 拒绝 | **1.8s** |
| 守卫全程生效 + 本节改进 | **34 正确 / 0 错答案 / 1 拒绝**（仅"拒绝的是哪一例"不同） | **146–188s** |
| 守卫全程生效、只有 `84705d9` 的事实 | 33 正确 / 0 错答案 / 2 拒绝 | 46.5s |
| 守卫全程生效、无任何事实 | —— | 挂死（30 分钟级） |

**正确性完全相同，代价两个数量级。** 最小复现：守卫生效时
`cas.integ(p^2*sqrt(1-p^2), p)` 单例要 **6.6s**（挂起时 0.05s 级），但返回的答案是
**对的**（`1/8*asin(p) - 1/32*sin(4*asin(p))`，实数形式）。

> 过程记录：我最初用 `-e` 单例测出"全部 < 0.5s"，那是**错的** —— 那批调用快速失败、
  没有真正跑完。改用同进程 `sys.clock()` 与最小脚本才看到真值 6.6s。
  **测量口径必须一致，且要确认"跑完了"而不是"快速失败了"。**

### 裁决

**对推导路径而言，守卫换不来任何正确性收益，只带来两个数量级的开销。** 故
`branchGuardsActive` 仍按推导期挂起，`5736e68` 的规则与事实在挂起期间**休眠**。

它们不是废码，而是**取消挂起时必须的前提**：把"圆分支消根式"从依赖不 sound 的通用
化简器，改成显式的、分支有据的 `applyRule` 规则。

### P2 判据的现状

原判据「四例给正确结果 + 推导期不再挂起守卫 + 耗时回到秒级」：

- 前两项**已达成**（正确性追平；四例里三例给出正确结果，与"拒绝对象"的差异只是换了一例）
- 第三项**未达成**（100 倍）

⇒ **按当前实现，P2 判为「不值得做」**。要继续，必须先解决"守卫下中间表达式规模膨胀"，
把搜索成本拉回挂起时的水平；否则取消挂起是纯亏。这是实测裁决，不是搁置。

## 15. "收窄挂起"实验（B4）：实测零效果 ⇒ 否证

### 缘起：记录里的那个边界在本代码里不存在

§14 留下的下一项是"把挂起收窄到 `doInteg` 的搜索阶段、回代阶段恢复守卫"。A0 轨迹诊断
（`D:\Temp\trace_a.jc2` → `trace_a_out.txt`）显示这个分界不存在：`integrate()` 的
`ScopedIntegrationScope`（`Integration.cpp:1325`）覆盖评分、`execute()`（换元 + 递归 +
回代 + 化简）、内部自检与出口 `simplify`，没有可切的"搜索/回代"两段。

### A0 轨迹事实（case A `p^2*sqrt(1-p^2)`）

- depth0 路由：Linear(1000) → Generalized(900) → Biquadratic(870) → Binomial(860) →
  **Radical(800) 返回**；其换元 `u = (1-p^2)^(1/2)` 把被积式变成 `-p^2*sqrt(p^2-1)*i`，
  **`i` 就是分支穿越点**（`trace_a_out.txt:12`）。
- 全程 **0 次** `rejected by self-check`；Radical 的错候选被内部自检放行 → 顶层返回 →
  出口自检拒绝 → 抛错。
- score 650 的 Trig 圆分支**从未被走到**（800 的 Radical 先返回）。

### B4 假设与实测：零效果

假设：内部自检 `checkAntiderivative`（`Integration.cpp:1271`）在挂起状态下化简残差，
通用重写把残差化成 0 从而放行错候选；只要在**自检处**临时恢复守卫
（新增 `ScopedBranchGuards`：`branchGuardsActive() = 挂起深度==0 || 强制生效深度>0`）即可。

实测结果：**零效果** —— A 仍抛错（0.062s，改动前 0.066s），B 仍正确（0.296s）；
带 B4 的轨迹与改动前**逐行相同**（419 行），`rejected by self-check` 仍为 0 次。

### 诊断（临时打印，随后回退）

case A 顶层候选的真实判决：

```
[CHECK numeric] Unknown valid=0 pass=0
residual = -p^2*sqrt(-p^2+1) + 1/16*exp(-4*acosh(sqrt(-p^2+1)))*p/sqrt(p^4-p^2)*i + ...
F        = (1/8*acosh(sqrt(-p^2+1)) + 1/64*exp(-4*acosh(...)) - 1/64*exp(4*acosh(...))) * i
```

- 内部自检的 5 个测试点**一个都数值化不了** ⇒ `valid_tests = 0` ⇒ **`Unknown`**；
  调用点 `Integration.cpp:3506` 只在 `Invalid` 时跳过 ⇒ 放行。
- 出口自检用**另一套求值器** `doEvalf`（`BuiltinRegistry.cpp:5798`）能求出数值 ⇒
  残差非零 ⇒ `Invalid` ⇒ 抛错。
- **守卫状态在这里完全无关**：残差在两种状态下都保持符号形式、都不可数值化。

⇒ 病灶是**两处自检的数值化能力不一致 + `Unknown` 从宽**，与分支守卫无关。
§14 里"守卫生效能修好 A"是因为路径变化使该 Radical 候选不再生成，代价 100×。

### 结论

- **"取消挂起"（§14）与"收窄挂起"（本节）均判为否证**；
  `branchGuardsActive()` / `ScopedIntegrationScope` 保持推导期整段挂起，不再重启 P2。
- 新问题独立记录（不属于本方案）：内部每策略自检的数值化能力弱于出口自检
  （`evalFloat` + `evalUniversal` vs `doEvalf`），且 `Unknown` 从宽；已单独修复，见 §16。

`e2e_scan` 34 正确 / 0 错 / 1 拒绝（拒绝 `p^2*sqrt(1-p^2)`），
